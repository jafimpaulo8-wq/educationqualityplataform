# MOZTECHWAVE EDUCATION PLATFORM

Plataforma de gestão académica do Centro de Formação Técnico Profissional Moztechwave (CFTPM), preparada para várias instituições. Nome comercial do módulo académico: **SIGAR PRO**.

## Arquitectura

- Interface: React, TanStack Router e TanStack Start.
- Autenticação: Better Auth (email e palavra-passe, Google e X através do broker).
- Dados da aplicação: Postgres. No preview é PGLite em `/workspace/.data/pglite`. Em produção usa `DATABASE_URL` (Neon).
- Firebase projecto `sigar-6754a`: leitura dos alunos já existentes. Contas novas da plataforma vão para a coleção `moztechwave_contas`. As coleções `alunos`, `students`, `payments` e as restantes não são apagadas nem reescritas por esta aplicação.
- Permissões: RBAC no servidor. O menu só esconde o que a regra já bloqueia.
- Isolamento: cada registo de negócio leva `institution_id`. Uma empresa com perfil `EMPRESA` só vê a empresa cujo email coincide com a conta.

## Instalação

```bash
npm install
npm run dev
```

O preview sobe em `http://127.0.0.1:8080`.

## Firebase

Configuração web usada no servidor:

- `projectId`: `sigar-6754a`
- Authentication: o login da plataforma é Better Auth. O Firebase Auth do projecto antigo não foi substituído.
- Firestore: leitura de `alunos` e `students`. Escrita apenas em `moztechwave_contas` ao criar uma conta nova.
- Storage e Cloud Functions: preparados, ainda sem deploy neste ambiente.

Não apague coleções existentes. Não altere campos de alunos já gravados no Firestore a partir desta plataforma.

## Variáveis

| Variável | Uso |
|---|---|
| `DATABASE_URL` | Postgres de produção. Vazio = PGLite local. |
| `BETTER_AUTH_SECRET` | Segredo da sessão. |
| `BETTER_AUTH_URL` | URL pública da aplicação. |
| `GROK_AUTH_ISSUER` | Broker Google/X. |
| `GROK_AUTH_CLIENT_ID` / `GROK_AUTH_CLIENT_SECRET` | Cliente OAuth. |
| `XAI_API_KEY` | Assistente, quando existir. |

## Deployment

`npm run build` e o arranque de produção do TanStack Start. Defina `DATABASE_URL` antes de publicar. As migrações em `migrations/` aplicam-se na primeira ligação. Ficheiros em `migrations/auth/` são o esquema do Better Auth.

## Migração

Importação CSV/JSON em `/app/importar`, com deduplicação por BI, código ou id. Não duplica um aluno se o documento já existir na instituição. Não escreve de volta no Firestore.

## Segurança

- Ninguém altera o próprio papel.
- Saldo, notas e certificados aprovados não se mudam no browser.
- Baixa de aluno não apaga histórico.
- Portaria não vê definições administrativas.
- Aluno, encarregado e empresa não vêem o painel financeiro da instituição.
- O link de um aluno não abre dados privados sem sessão.
